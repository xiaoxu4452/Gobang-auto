──────────────────────────────────────────────────
摘 要
──────────────────────────────────────────────────
Meter 五子棋助手（单机版）是一款运行于 Windows 桌面的五子棋对弈辅助软件。
软件通过屏幕识别服务实时捕获对弈软件棋盘区域内的落子状态，调用本机原生
棋力引擎对局面进行深度评估，并将「推荐落点、胜率热力图、对手意图预测、
平衡选点」等分析结果以图形叠加层（Overlay）与浮动面板的形式呈现给用户。

单机版区别于三件套装（书签版 / 桌面助手 / 训练器）的核心设计在于其
「单硬连接」运行模型：助手宿主进程直接创建并持有识别服务进程与原生棋力
引擎进程，引擎生命周期与助手严格同步——助手启动即就绪，助手退出即随宿主
整体回收。该模型不依赖任何共享调度服务，因而不存在多客户端竞争、
收养过户与连接失效问题；重启助手即获得全新引擎，连接在结构上不可能失效。

本软件的全部计算（棋盘识别、引擎搜索）均在本地完成，不经网络传输任何
棋局数据；软件亦不联网上传用户信息。

──────────────────────────────────────────────────
第一章 系统要求
──────────────────────────────────────────────────
1.1 硬件与操作系统
  · 操作系统：Windows 10（build 1809+）或 Windows 11，64 位。
  · 处理器：x86-64 架构。软件随附五种指令集档位的引擎变体
    （AVX512-VNNI / AVX-VNNI / AVX512 / AVX2 / SSE），启动时自动探测
    CPU 能力并现场冒烟验证，选择本机可运行的最强档位。
  · 内存：≥ 8 GB（建议 16 GB；引擎哈希表可配置，详见第七章）。
  · 显示：引擎评估图形叠加需要正常的桌面合成（DWM），远程会话可用
    但识别帧率可能下降。

1.2 运行组件
  · Microsoft Edge WebView2 Runtime：Windows 11 与多数 Windows 10 已随
    Edge 预装。若缺失，安装器会提示并引导至官方下载页（一次性）。
    面板界面由 WebView2 渲染；渲染内核随系统 Edge 渠道自动更新。

1.3 端口与网络
  · 本软件为单机运行模型，不监听任何对外网络端口，不发起任何互联网连接。
  · 识别服务与面板界面均在进程内通信（命名管道 / 进程内资源拦截），
    不占用任何 TCP 端口，不与防火墙交互。

第二章 产品架构与工作原理
──────────────────────────────────────────────────
2.1 模块组成
  ┌────────────────────────────┬────────────────────────────────────┐
  │ 模块                        │ 职责                                │
  ├────────────────────────────┼────────────────────────────────────┤
  │ Desktop GomokuAssistant.exe │ 宿主：窗口/叠加层/面板供给/进程编排   │
  │ Vision\GomokuVision.exe     │ 识别服务：屏幕抓帧 → 棋盘定位 → 读子 │
  │ Vision\GomokuVision.dll     │ 识别模型库（与 exe 成对）           │
  │ rapfi-native\               │ 原生棋力引擎（五种 ISA 变体）+ 权重  │
  │ overlay\                    │ 加密面板界面（运行时内存解密）       │
  └────────────────────────────┴────────────────────────────────────┘

2.2 识别管线
  宿主启动后拉起识别服务，识别服务对屏幕按「帧差分看门」节奏工作：
  棋盘位置锁定后，每约 33ms 仅对棋盘矩形做一次降采样灰度差分；
  画面静态时不执行任何重量级识别运算；检测到落子/提子/棋盘移动后
  立即触发完整识别（边缘定位 → 网格精化 → 逐子颜色判定）。
  该设计使静态局面下的识别开销接近于零，而落子响应进入百毫秒量级。

2.3 引擎连接（单硬连接模型）
  助手宿主以「直接子进程 + 作业对象（Job Object）」方式持有原生引擎：
    · 启动：宿主按 CPU 探测结果启动 RapfiEngine 变体进程，
      通过标准输入/输出直连（无 HTTP、无中间调度器）；
    · 运行：引擎随宿主常驻，评估请求由面板经进程内通道直达宿主；
    · 退出：宿主正常退出时优雅关停引擎（落盘引擎数据库）；
      宿主异常终止时，作业对象保证引擎被系统整体回收。
  因此「重启助手后引擎连接失效」这类问题在单机版中结构性不存在。

2.4 面板供给
  面板界面文件以加密形态随包发布（overlay\*.enc），宿主在内存中解密
  后经进程内资源通道供给 WebView2，磁盘上不落明文。模型文件同样经
  进程内通道供给，全程无 TCP 套接字。

──────────────────────────────────────────────────
第三章 安装
──────────────────────────────────────────────────
3.1 安装步骤
  ① 双击「Meter GomokuAssistant_Setup.exe」。
  ② 选择界面语言（中文 / English）。
  ③ 安装位置默认 %LOCALAPPDATA%\Programs\Meter GomokuAssistant
    （单用户安装，不弹管理员授权）。
  ④ 勾选「创建桌面快捷方式」可生成「Meter 五子棋助手」桌面图标。
  ⑤ 安装完成页可直接启动。若系统缺 WebView2，安装器会先给出
    补装指引（点「是」打开官方下载页，装完回来继续即可）。

3.2 升级安装
  直接运行新版本安装包，安装器自动清理旧版面板、引擎与识别组件后
  覆盖安装，用户无需手动卸载。

──────────────────────────────────────────────────
第四章 快速上手
──────────────────────────────────────────────────
① 启动：双击「Meter 五子棋助手」。首次启动显示品牌遮罩并完成环境
   自检（约数秒），随后出现浮动面板与全屏角框参考层。
② 选定棋盘：将面板「棋盘」按钮指向对弈软件的棋盘窗口，或按面板
   提示框选棋盘区域。识别服务锁定棋盘后，屏幕上以四角框标定范围。
③ 开始对弈：双方正常落子，助手自动跟随局面并给出：
   · 蓝圈——引擎推荐落点（按胜率排序，可显示多选）；
   · 热力图——全盘胜率热力（四档强度）；
   · 预测环——对手最可能落点的预测标注；
   · 胜率条——当前局面倾向。
④ 平衡选点：交换手/平衡局中，点击「平衡」按钮，引擎在候选点中
   寻找双方胜率最接近 50% 的落点，用于让先与交换规则。
⑤ 局面回放：「局面」小窗支持查看当前局面代码、保存局面文本。

──────────────────────────────────────────────────
第五章 功能详解
──────────────────────────────────────────────────
5.1 棋盘识别
  · 自动适配 15×15 标准五子棋盘（含无禁手/有禁手规则显示）；
  · 支持棋盘窗口移动后的自动跟随（角框按位移增量平移）；
  · 棋盘几何锁定失效率过高时自动回退全量识别，无需人工干预。

5.2 推荐与热力
  · 蓝圈推荐点数量、热力图开关均在面板设置区切换；
  · 引擎搜索深度随思考时间预算自动分配（详见第七章）。

5.3 平衡选点
  基于引擎原生平衡指令迭代完成，返回点集按「双方胜率接近度」排序；
  若局面已存在成五点，软件会明确提示「当前为必胜局面」而非给出
  误导性的平衡点。

5.4 界面
  · 中英双语即时切换；深浅色主题跟随系统；
  · 面板可拖动、置顶；拖动时识别叠加自动让路，互不遮挡。

──────────────────────────────────────────────────
第六章 引擎与视觉模型
──────────────────────────────────────────────────
6.1 原生引擎（rapfi-native\）
  引擎为 Rapfi 0.43.01 官方 Windows 构建（上游 https://github.com/dhbloo/rapfi，
  GPLv3 许可，详见《开源许可与版权声明》）。随包五种变体按算力强度排序：
    RapfiEngine-avx512vnni.exe   AVX512F/DQ/BW/VL + AVX512_VNNI（最强）
    RapfiEngine-avxvnni.exe      AVX-VNNI（VEX；Intel Alder Lake+ / AMD Zen5+）
    RapfiEngine-avx512.exe       AVX512F/DQ/BW/VL
    RapfiEngine-avx2.exe         AVX2 + FMA + BMI2
    RapfiEngine-sse.exe          基线（任意 x64）
  选择策略：CPUID 全量探测（含操作系统状态位）→ 真实 300ms 冒烟搜索
  验证 → 通过即用；失败自动降档。冒烟结论绑定本机 CPU 指纹缓存于
  rapfi-native\.variant-ok，换机自动失效重探。

6.2 权重与规则
  权重采用 classical 旧格式（model210901.bin，23 204 字节），
  与官方 250615 构建配套，请勿以其他版本替换。

6.3 视觉模型（Vision\）
  识别服务为自包含 C++ 实现（OpenCV 内核，Apache-2.0 许可），
  识别模型库 GomokuVision.dll 与 exe **成对**使用，二者必须同版本。

──────────────────────────────────────────────────
第七章 性能调优
──────────────────────────────────────────────────
· 线程数：面板设置中可调引擎线程。默认按物理核数自动分配；
  高核数机器建议给引擎 2/3 以上算力并保留系统余量。
· 哈希：默认按内存自动；对弈频繁/机器内存充裕时可调大，
  引擎将获得更深的搜索稳定度。
· 帧率：识别为事件驱动（帧差分看门），无需手动配置；
  若对弈软件渲染异常导致识别抖动，可尝试关闭对弈软件的动画特效。

──────────────────────────────────────────────────
第八章 常见问题与排障
──────────────────────────────────────────────────
Q1 面板空白或黑屏？
  多为 WebView2 缺失或损坏。到「设置 → 应用」确认 Microsoft Edge
  WebView2 Runtime 存在；或重装 Edge 后重试。日志（logs\overlay-*.log）
  中搜索 [wv2] 可得直接原因。

Q2 四角框出现了，但识别不到棋盘？
  确认框选区域完整包含棋盘且无遮挡；深色主题棋盘、异形皮肤棋盘
  支持有限。日志中搜索 [scan] 可见识别耗时与失败原因。

Q3 引擎评估一直转圈？
  查看日志 [engine] 段：若出现「变体降档」，说明本机 CPU 不支持当前
  档位，软件已自动换档，属正常现象；若反复出现引擎进程退出
  （0xC0000005/0xC000001D），多为安全软件拦截——请把 rapfi-native\
  目录加入白名单。

Q4 换电脑后第一次启动很慢？
  首次启动需完成 ISA 冒烟探测（每个候选变体 ≤5 秒），结论缓存后
  后续启动直接复用。

Q5 平衡按钮返回「必胜局面」提示？
  局面已存在成五点，平衡无意义。这是甄别机制的正常输出。

Q6 想彻底重置？
  退出软件后删除安装目录内 rapfi-native\rapfi.db（引擎自学习数据库）
  与 logs\（日志）即可，不影响主程序。

──────────────────────────────────────────────────
第九章 卸载与数据清理
──────────────────────────────────────────────────
· 系统设置 → 应用 → Meter GomokuAssistant → 卸载。
  卸载器会先结束助手、引擎与识别服务进程，再移除全部程序文件。
· 以下运行期产物由卸载器一并清理：WebView2Data\（浏览器用户数据）、
  logs\（运行日志）。
· 引擎自学习数据库 rapfi.db 在 rapfi-native\ 内，随目录一并移除。
