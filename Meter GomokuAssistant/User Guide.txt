This guide is the complete reference for the Meter GomokuAssistant
(Standalone Edition). It is organised as: Abstract — Requirements —
Architecture — Installation — Features — Engine & Models — Tuning —
Troubleshooting — Uninstall — Appendix. Please read Chapter 1 and
Chapter 3 in full before installing.

See the accompanying "LICENSES & COPYRIGHT NOTICES.txt" for the
third-party open-source components and their license terms.

──────────────────────────────────────────────────
ABSTRACT
──────────────────────────────────────────────────
Meter GomokuAssistant (Standalone) is a Windows desktop assistant for
Gomoku (five-in-a-row). It captures the board area of your game window
in real time, evaluates the position with a native on-device engine,
and presents recommendations — best-move circles, win-rate heatmap,
opponent-intent markers, and balance points — as a transparent overlay
and a floating panel.

The defining design of the Standalone Edition is its single hard C++
connection model: the host process directly owns both the vision
service process and the native engine processes. Engine lifetime is
strictly bound to the assistant — ready at launch, reclaimed as a
whole at exit. There is no shared scheduler, no ownership handshake,
and therefore no "connection lost after restart" failure class: every
restart yields a freshly loaded engine and model.

All computation (board recognition and engine search) is performed
locally. The software does not transmit any game data over the network.

──────────────────────────────────────────────────
CHAPTER 1  SYSTEM REQUIREMENTS
──────────────────────────────────────────────────
1.1 Hardware and OS
  · Windows 10 (build 1809+) or Windows 11, 64-bit.
  · CPU: x86-64. Five engine ISA variants ship in the package
    (AVX512-VNNI / AVX-VNNI / AVX512 / AVX2 / SSE); the strongest
    runnable one is selected at startup by CPUID plus a real 300 ms
    smoke search.
  · RAM: 8 GB minimum (16 GB recommended; engine hash is configurable).
  · Display: normal desktop composition (DWM). Remote sessions work
    but recognition frame rate may drop.

1.2 Runtime component
  · Microsoft Edge WebView2 Runtime — preinstalled with Edge on most
    systems. If missing, the installer offers the official download
    link once.

1.3 Ports and network
  · The assistant listens on no network ports and makes no internet
    connections. Vision and panel communicate in-process (named pipe /
    WebResource interception); no TCP sockets are involved.

──────────────────────────────────────────────────
CHAPTER 2  ARCHITECTURE
──────────────────────────────────────────────────
2.1 Components
  Desktop GomokuAssistant.exe   Host: overlay windows, panel serving,
                                process orchestration (C++).
  Vision\GomokuVision.exe       Vision service: screen capture,
                                board locating, stone reading.
  Vision\GomokuVision.dll       Vision model library (paired with exe).
  rapfi-native\                 Native engine (five ISA variants),
                                weights and configuration.
  overlay\*.enc                 Encrypted panel UI (decrypted in RAM).

2.2 Vision pipeline
  After the board is located, a frame-difference watch thread samples
  only the board rectangle at ~30 fps with a 96×96 grayscale hash.
  While the position is static, no heavy recognition runs at all;
  a stone change wakes the full pipeline (edge locating → grid
  refinement → stone reading) immediately. Static cost is near zero
  and move response is in the hundred-millisecond range.

2.3 Engine connection (single hard C++ connection)
  The host starts the best runnable RapfiEngine variant as a direct
  child process, talking over stdin/stdout pipes — no HTTP, no Node
  scheduler. All engine lanes are members of a Job Object with
  KILL_ON_JOB_CLOSE: when the assistant exits (even on crash), the
  engine processes are reclaimed by the system as a whole. On restart
  the engine and its model are loaded anew; stale-connection states
  cannot exist by construction.

2.4 Panel serving
  Panel UI files ship encrypted and are decrypted in memory by the
  host, served to WebView2 via in-process request interception.
  Engine commands and outputs travel the same in-process channel —
  zero TCP end to end.

──────────────────────────────────────────────────
CHAPTER 3  INSTALLATION
──────────────────────────────────────────────────
① Run "Meter GomokuAssistant_Setup.exe".
② Choose the interface language (中文 / English).
③ Default location: %LOCALAPPDATA%\Programs\Meter GomokuAssistant
   (per-user install, no UAC prompt).
④ Optionally create a desktop shortcut ("Meter 五子棋助手" in Chinese
   mode / "Meter GomokuAssistant" in English mode).
⑤ Launch from the finish page. If WebView2 is missing, the installer
   guides you to the official download page first.

Upgrades: run the new installer over the old one; the panel, engine
and vision components are cleaned and replaced automatically.

──────────────────────────────────────────────────
CHAPTER 4  QUICK START
──────────────────────────────────────────────────
① Launch the assistant. A brand splash runs environment checks for a
   few seconds, then the floating panel and fullscreen corner markers
   appear.
② Aim the board selector at your game's board window (or drag-select
   the region). Locked boards are marked with corner frames.
③ Play normally. The assistant follows the position and shows:
   · Blue circles — engine-recommended moves (ranked by win rate);
   · Heatmap — board-wide win-rate heat in four intensities;
   · Prediction ring — the opponent's most likely point;
   · Win-rate bar — the current evaluation trend.
④ Balance points: in swap/balanced openings, press "Balance" and the
   engine searches for moves whose win rate is closest to 50 %.
⑤ Position window: inspect and save the current position code.

──────────────────────────────────────────────────
CHAPTER 5  FEATURES IN DETAIL
──────────────────────────────────────────────────
5.1 Recognition
  · Fits standard 15×15 boards; follows window moves by delta
    translation; falls back to full recognition automatically when
    the locked-geometry liveness drops.
5.2 Recommendations
  · Circle count, heatmap and prediction toggles live in the panel
    settings; search depth follows the per-move time budget.
5.3 Balance
  · Built on the engine's native balance search (YXBALANCEONE/TWO
    with YXBLOCK iteration). If a winning five already exists, the
    panel states "decisive position" instead of fake balance points.
5.4 UI
  · Instant Chinese/English switch; dark/light theme follows the OS;
    draggable always-on-top panel; the overlay yields during drags.

──────────────────────────────────────────────────
CHAPTER 6  ENGINE AND MODELS
──────────────────────────────────────────────────
6.1 Native engine (rapfi-native\)
  Rapfi 0.43.01 official Windows builds (upstream
  https://github.com/dhbloo/rapfi, GPLv3 — see the license notices).
  Variants, strongest first:
    RapfiEngine-avx512vnni.exe   AVX512F/DQ/BW/VL + AVX512_VNNI
    RapfiEngine-avxvnni.exe      AVX-VNNI (VEX; Intel Alder Lake+ / AMD Zen5+)
    RapfiEngine-avx512.exe       AVX512F/DQ/BW/VL
    RapfiEngine-avx2.exe         AVX2 + FMA + BMI2
    RapfiEngine-sse.exe          baseline (any x64)
  Selection: full CPUID probing (including OS state bits) → real
  300 ms smoke search → downgrade automatically on failure. The
  result is cached in rapfi-native\.variant-ok together with a CPU
  fingerprint; copying the folder to another machine invalidates it.

6.2 Weights
  classical old-format (model210901.bin, 23 204 bytes), matched to the
  official 250615 builds. Do not substitute other weight files.

6.3 Vision (Vision\)
  Self-contained C++ implementation (OpenCV core, Apache-2.0 — see
  the license notices). GomokuVision.dll must always ship paired with
  GomokuVision.exe at the same build.

──────────────────────────────────────────────────
CHAPTER 7  PERFORMANCE TUNING
──────────────────────────────────────────────────
· Threads: configurable in the panel. The engine lane budget defaults
  to two thirds of the logical cores, leaving headroom for vision,
  panel and the system.
· Hash: defaults to one third of RAM (capped at 4 GB); larger values
  deepen search stability on memory-rich machines.
· Frame rate: recognition is event-driven; no manual configuration.
  If your game renders with heavy animation effects, disabling them
  steadies recognition.

──────────────────────────────────────────────────
CHAPTER 8  TROUBLESHOOTING
──────────────────────────────────────────────────
Q1 Blank or black panel?
  Usually missing/broken WebView2. Verify "Microsoft Edge WebView2
  Runtime" exists; reinstall Edge if needed. Search the logs
  (logs\overlay-*.log) for [wv2] lines.

Q2 Corner frames show but no board is found?
  Ensure the region fully contains the board without occlusion.
  Dark-themed or skinned boards have limited support. [scan] log
  lines show timing and failure reasons.

Q3 Engine evaluation keeps spinning?
  Check [engine] log lines. "variant downgrade" messages are normal
  self-healing. Repeated exits with 0xC0000005/0xC000001D usually
  mean antivirus interception — whitelist the rapfi-native folder.

Q4 First launch on a new machine is slow?
  ISA smoke probing runs once per candidate variant (≤5 s each);
  results are cached for subsequent launches.

Q5 Balance says "decisive position"?
  A five-in-a-row already exists; balancing is meaningless there.
  This is the guard working as designed.

Q6 Full reset?
  Exit, then delete rapfi-native\rapfi.db (engine self-learning
  database) and logs\. The main program is not affected.

──────────────────────────────────────────────────
CHAPTER 9  UNINSTALL AND DATA CLEANUP
──────────────────────────────────────────────────
· Windows Settings → Apps → Meter GomokuAssistant → Uninstall.
  The uninstaller stops the assistant, engine and vision processes,
  then removes all program files.
· Runtime artifacts removed as well: WebView2Data\ and logs\.
· The engine database rapfi.db lives inside rapfi-native\ and is
  removed with the directory.
